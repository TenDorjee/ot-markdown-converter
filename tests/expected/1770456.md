# CVE-2021-44228, CVE-2021-45046 and CVE-2021-45105 in AutoPass license server

## Summary

AutoPass license server (APLS) versions impacted by CVE-2021-44228, CVE-2021-45046 and CVE-2021-45105.

**SUPPORTED SOFTWARE VERSIONS\*: ONLY impacted versions are listed.**\
APLS version: 11.7.\*, 11.8.\*, 11.9.\*, 12.0.\*, 12.1.0, 12.1.1, 12.1.2\

**Question:** Is AutoPass License Server (APLS) Impacted by CVE-2021-44228, CVE-2021-45046 and CVE-2021-45105?\
**Answer:** Yes, Please refer the above table for Impacted APLS versions against CVEs.

**Question:** Is Patch Available for this?\

**Question:** For APLS version 11.7.0 to 12.1.0, is there Mitigation for this CVEs without Upgrade to latest version?\
**Answer:** Yes\
**Option1:**\

**Question:** Are APLS versions 10.7.0 to 11.6.0 are impacted with **CVE-2021-45046, CVE-2021-44228 and CVE-2021-45105?**

**Answer**: No,\
APLS version 10.7.0 to 11.6.0 uses log4j 1.2.15 for logging. In the (\autopass\apls\apls\webapps\autopass\WEB-INF\lib\\) folder log4j-core-2.11 is present but it is not used by Application for logging. This is confirmed by certifying APLS version 10.7.0 to 11.6.0 by deleting log4j-core-2.11.jar file from the lib folder. Hence this is false positive for APLS version 10.7.0 to 11.6.0\
This analysis is based on the bulletin below.\
<https://logging.apache.org/log4j/2.x/security.html>

Extract from the bulletin:\
Note that only the log4j-core JAR file is impacted by this vulnerability. Applications using only the log4j-api JAR file without the log4j-core JAR file are not impacted by this vulnerability.

Versions Affected: all versions from 2.0-beta9 through 2.12.1 and 2.13.0 through 2.15.0

**Log4j 1.x mitigation**: Log4j 1.x is not impacted by this vulnerability.

**Question:** log4j-core-2.x.jar version <= 2.16 is present in autopass.war file and detected as vulnerability in security scans, what is the impact and how to mitigate this?

The log4j-core.2.X.jar present in autopass.war file in webapps folder of autopass installation directory is not used by application, but it is part of web Archive (.WAR) of APLS installation and is used by Tomcat to unpack all the project files from the WAR file in a new directory named after the project (autopass). The files inside autopass.war is not used once it is unpacked, so log4j-core.2.x.jar present inside jar will not cause any issue and should be treated as false positive.

If you must delete the war file to avoid scans reporting log4j.core-2.x<=2.16, then please follow the below steps\
1\) stop the Autopass License server service\
2\) Take the backup of autopass.war folder under “autopass\apls\apls\webapps”\
3\) delete the .war file\
4\) Start the Autopass License server service\
5\) Verify that autopass folder is still present in webapps after restart\
6\) Access the application UI to confirm that autopass is started after restart

To Delete the log4j.core-2.x<=2.16 file from WAR file without deleting WAR file,

1. Stop the APLS service
2. In Windows:

open WAR file with WINRAR iand delete the WEB_INF\lib\log4j-core-2.x.jar and save it

In Linux use command“zip -q -d autopass.war WEB-INF/lib/log4j-core-2.11.0.jar ” from webappas folder\
Note: For APLS version 10.7 to 11.6.0 delete log4j-core-2.11.0.jar, from APLS version 11.6 to 12.1.0 delete log4j-core.13.3.jar

3\) start the service
