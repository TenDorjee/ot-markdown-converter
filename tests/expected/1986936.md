# How to Configure UFT One/UFT Developer for Reliable Test Execution on Locked or Disconnected Remote Sessions.

## Summary

This article outlines best practices and recommended configurations to ensure that UFT One (OpenText Functional Testing) scripts continue to run reliably when executed in remote, locked, or disconnected desktop sessions. These recommendations are especially important for unattended, scheduled, or CI/CD-driven executions where no user is physically present.

## Environment

- UFT One Version: Any
- UFT Developer: Any
- Operating System: All supported versions of Microsoft Windows
- Browsers: Google Chrome, Microsoft Edge, Mozilla Firefox
- Test Type: GUI tests using WPF, Web, and .NET Add-ins
- Remote Execution: Remote Desktop Protocol (RDP) / Virtual Desktop Infrastructure (VDI) / Virtual Machines (VMware, Azure, etc.)

## Situation

When running UFT tests remotely using Remote Desktop Protocol (RDP) or on virtual desktop infrastructure (VDI), the remote session may lock or disconnect, causing the UFT test to fail. This happens because UFT needs an active, unlocked desktop session to properly interact with the application under test.

If common troubleshooting approaches, such as those outlined in the UFT documentation here:\
[Running Tests from Remote Desktop Connections](https://admhelp.microfocus.com/uft/en/25.2/UFT_Help/Content/User_Guide/Tr_Lim_Running_TEST.htm#mt-item-1) or [Running and Debugging Tests](https://admhelp.microfocus.com/uft/en/25.2/UFT_Help/Content/User_Guide/UFT_Opt_Gen_Run.htm#continued) do not resolve the issue, the strategies discussed in this guide may help maintain test stability.

These best practices are particularly important for scenarios such as:

- Steps involving keyboard input or window focus
- Capturing screenshots or screen recordings (black screen issues)
- Device-level replay (physical mouse interactions instead of browser events)
- Long-running or unattended test executions

## Cause

UFT One requires an active Windows user session with full graphical (interactive) desktop context to execute GUI-based test steps successfully. System-level configurations, such as security policies, session timeouts, power management settings, or virtualization behaviors can disrupt the graphical session by locking, suspending, or disconnecting it. When this occurs, UFT is unable to interact with the application under test, resulting in test step failures.\
To support remote and unattended executions, UFT can be configured to automatically establish a Windows session using predefined credentials. When remote execution is properly configured and enabled in UFT, a Windows user session is automatically initiated whenever the machine is logged off, restarted, or accessed remotely, allowing tests to run without requiring manual login.

This mechanism depends on the Polling feature, which must be correctly configured. The “Poll to Detect Disconnect” option allows UFT to periodically check the status of the remote session instead of relying solely on system-generated disconnect notifications. By polling the session state, UFT can continue interacting with the desktop even if the session state changes unexpectedly, improving execution reliability.

However, in environments governed by strict organizational or security policies, these policies may interfere with session creation, polling behavior, or credential-based logins. As a result, UFT may be unable to re-establish or maintain the interactive session, leading to failures when the session is locked, disconnected, or logged off.

The configuration recommendations and workarounds outlined in this article are intended to help mitigate these limitations and maintain stable UFT test execution in such constrained environments.

## Solution

### 1. Disconnect Remote Desktop Without Locking the Session

When you disconnect normally from RDP, Windows locks the session, breaking GUI access for UFT. Instead, use the following method to disconnect while keeping the session active and unlocked.

#### Method 1: Using Command Prompt Directly

- Open Command Prompt on the remote machine as Admin.
- Execute the following command:

```
for /f "skip=1 tokens=3" %s in ('query user %USERNAME%') do (tscon.exe %s /dest:console)
```

#### Method 2: Using a Batch File

- On the remote computer, create a batch file (like disconnect.cmd or disconnect.bat) with this line of code inside:

```
for /f "skip=1 tokens=3" %%s in ('query user %USERNAME%') do (tscon.exe %%s /dest:console)
```

Step 1: Create the Shortcut

- Right-click on the batch file, select Send to, then choose Desktop (create shortcut).

Step 2: Configure the Shortcut to Run as Administrator

- On your desktop, right-click the newly created shortcut and select Properties.
- Click the Advanced button.
- Check Run as administrator, then click OK and Apply.

Step 3: Use the Shortcut to Disconnect

- Double-click the shortcut whenever you need to disconnect from your Remote Desktop session.
- This will disconnect your session but keep it running with full graphical context.

### Troubleshooting Disconnect Issues

If the shortcut fails to disconnect the session, follow these steps:

- Open Command Prompt as Administrator.
- Run the following command to identify your current session name:

```
echo %SESSIONNAME%
```

If the session name is not empty, attempt to disconnect using one of the commands below:

```
tscon.exe %SESSIONNAME% /dest:console
```

or, if a password is required:

```
tscon.exe %SESSIONNAME% /dest:console /password:*
```

If You Receive Error 5023 or "Session name not found":

- Run the command “query session” in CMD.
- Locate the ID of your active session in the list.

Then disconnect using:

```
tscon.exe <ID> /dest:console
```

If the Session Name Is Empty:

Try one of the following PowerShell commands in CMD.

```
powershell -Command "& {$sid = (Get-Process -PID $pid).SessionID;tscon $sid /dest:console}"
```

or

```
powershell -NoProfile -ExecutionPolicy unrestricted -Command "& {$sid = (Get-Process -PID $pid).SessionID;tscon $sid /dest:console}"
```

These commands identify the current session ID programmatically and return control to the local console while keeping the session active and unlocked.

### 2. Power & Lock Screen Settings

Ensure the system is configured to prevent automatic locking or sleep mode by following these steps:

Adjust Power Settings:

- Set both the display and sleep options to Never in the Power & Sleep settings.

Disable Screen Savers:

- Confirm that any active screen savers are disabled.

Update Group Policy to prevent automatic locking:

- Run gpedit.msc

Modify Group Policy to Prevent Automatic Locking:

- Open the Group Policy Editor by running `gpedit.msc`.
- Navigate to:\
  `Computer Configuration` > `Windows Settings` > `Security Settings` > `Local Policies` > `Security Options`.
- Locate the policy named “Interactive logon: Machine inactivity limit” and set its value to 0.

### 3. RDP Session Timeout Configuration

To prevent Windows from terminating RDP sessions:

Step 1. Open gpedit.msc

Step 2. Navigate to: Computer Configuration> Administrative Templates> Windows Components> Remote Desktop Services> Remote Desktop Session Host> Session Time Limits

Step 3.

- Set time limit for disconnected sessions: Never
- Set time limit for active but idle sessions: Never
- End a disconnected session: Disabled

### 4. Enable Software Secure Attention Sequence (SAS)

If remote execution issues persist, modify the Secure Attention Sequence (SAS) policy:

Step 1. On the UFT machine, open gpedit.msc\
Step 2. Navigate to: Computer Configuration> Administrative Templates> Windows Components> Windows Logon Options> Disable or enable software Secure Attention Sequence.

Step 3. Configure:

- Enable Software Secure Attention Sequence
- Select Service and Ease of Access applications

Step 4. Restart the machine

⚠ Caution:\
Enabling this policy may pose a security risk, as it allows applications or services to log on remotely. Ensure the UFT machine does not contain sensitive data and complies with organizational security guidelines.

### 5. Virtual Environment–Specific Settings

#### VMware Workstation / Player

Step 1. Power off the virtual machine\
Step 2. Edit the .vmx file\
Step 3. Add: suspend.disabled = "TRUE"

This prevents the VM from suspending when the console is disconnected.

#### Azure / RDP-Based Virtual Machines

- Ensure RDP session time limits are disabled (see section 3)
- Prevent auto-disconnect or idle session termination
- Avoid VM suspension or shutdown by policies or schedules

### 6. Keep the VDI Session Visible

Some VDI platforms (for example, VMware Horizon) allow sessions to remain visible even after client disconnect.

- Enable Keep-Alive / Session Persistence settings where available
- Consult your VDI administrator for platform-specific options

### 7. Bypass Environment Checks for Locked or Logged-Off Detection

In special scenarios where UFT incorrectly reports the environment as locked or logged off, follow the steps outlined in: <https://my.opentext.com/support/article/2251771>

### 8. Configure DCOM Settings for UFT

Manually configure the DCOM identity for UFT:

Set "QuickTest Professional Application" DCOM identity to "The interactive user"

Follow the instructions in: <https://my.opentext.com/support/article/1687908>

### 9. Configure Windows Power Mode for Long-Running Test Execution

To help prevent performance degradation, sleep-related interruptions, or resource throttling during unattended test execution, configure the Windows power mode appropriately.

#### Recommended Power Modes

- Best power efficiency: Maximizes battery life. Suitable when working away from a power source, but may reduce performance.
- Balanced: Recommended for most users. Provides a balance between system performance and power consumption.
- Best performance: Maximizes system performance and is recommended for long-running or resource-intensive UFT executions. This setting consumes more power and is best used when the machine is connected to a charger.

#### Configure Power Mode in Windows 11

- Open Settings.
- Navigate to System > Power & battery.
- Under Power mode, select Best performance.

Note: For dedicated UFT execution machines, virtual machines, or remote execution environments, OpenText recommends using Best performance to minimize the risk of execution delays caused by power-saving features.

For more information, see Microsoft's documentation: [Change the power mode for your Windows PC.](https://support.microsoft.com/en-us/windows/change-the-power-mode-for-your-windows-pc-c2aff038-22c9-f46d-5ca0-78696fdf2de8)

## Additional Information

- If your organization’s security policies enforce system-level locking, any configuration changes made to avoid automatic session locking may be overridden by these restrictions. In such cases, it is important to work with your IT security team to explore potential exceptions or permissions that could be applied to allow uninterrupted UFT test executions.
- These steps are especially important for unattended test executions and continuous integration environments where no user is physically present.
